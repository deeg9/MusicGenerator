**Sign-up server action (`src/app/signup/actions.ts`):**
- `'use server'` directive
- Export `async function signup(formData: FormData)` that:
  - Extracts email, password, and next from formData
  - Creates Supabase server client via `createClient()`
  - Calls `supabase.auth.signUp({ email, password })`
  - On error: returns `{ error: string }` (friendly message mapping — map "User already registered" to "Hmm, that email's already taken. Try logging in instead?")
  - On success: calls `revalidatePath('/', 'layout')` then `redirect(next || '/dashboard')`
  - Email confirmation is disabled for v4.2, so user gets session immediately after signup

**Login page (`src/app/login/page.tsx`):**
- Same centered card layout as signup
- Libre Baskerville heading: "Welcome back"
- Fields: email input, password input (no min length for login — just non-empty)
- Password visibility toggle (same as signup)
- Baby blue primary submit button: "Log in" with loading state
- Client-side validation with `loginSchema`
- Server-side error banner: "Hmm, that doesn't look right. Check your email and password?" (for invalid credentials)
- Cross-link: "Don't have an account? [Sign up](/signup)" — preserve `next` query param
- "Forgot your password?" link below password field, linking to `/forgot-password`
- Read and pass `next` query param same as signup

**Login server action (`src/app/login/actions.ts`):**
- `'use server'` directive
- Export `async function login(formData: FormData)` that:
  - Extracts email, password, and next from formData
  - Creates Supabase server client
  - Calls `supabase.auth.signInWithPassword({ email, password })`
  - On error: returns `{ error: "Hmm, that doesn't look right. Check your email and password?" }`
  - On success: `revalidatePath('/', 'layout')` then `redirect(next || '/dashboard')`

**Forgot password page (`src/app/forgot-password/page.tsx`):**
- Client Component for form interactivity
- Same centered card layout as login/signup
- Libre Baskerville heading: "Reset your password"
- Body text: "Enter your email and we'll send you a link to reset your password."
- Single email field with Zod validation (`forgotPasswordSchema`)
- Baby blue primary submit button: "Send reset link" with loading state
- On success: replace the form with an inline success message (per research discretion recommendation — no separate /sent route):
  - Heading: "Check your inbox"
  - Body: "We sent a password reset link to {email}."
  - PKCE hint: "Open the link on this device for it to work." in subtle muted text (per user decision — not alarming, just helpful)
  - Link back: "Back to [log in](/login)"
- On error: banner above form with friendly message

**Forgot password server action (`src/app/forgot-password/actions.ts`):**
- Export `async function resetPassword(formData: FormData)`:
  - Extracts email
  - Calls `supabase.auth.resetPasswordForEmail(email, { redirectTo: '${origin}/auth/confirm' })` where origin comes from `headers().get('origin')` or env var `NEXT_PUBLIC_SITE_URL`
  - On error: returns `{ error: string }`
  - On success: returns `{ success: true }`
  - Note: do NOT redirect — the page handles inline success display

**Update password page (`src/app/update-password/page.tsx`):**
- Client Component
- Same centered card layout
- Libre Baskerville heading: "Set your new password"
- Single password field with visibility toggle, validated with `updatePasswordSchema` (min 8 chars)
- Baby blue primary submit button: "Update password" with loading state
- Error banner for server-side errors

**Update password server action (`src/app/update-password/actions.ts`):**
- Export `async function updatePassword(formData: FormData)`:
  - Extracts password
  - Calls `supabase.auth.updateUser({ password })`
  - On error: returns `{ error: string }`
  - On success: `redirect('/dashboard')`

**Auth confirm callback (`src/app/auth/confirm/route.ts`):**
- Export `async function GET(request: NextRequest)`:
  - Extract `token_hash` and `type` from searchParams
  - Extract `next` from searchParams (defaults to '/')
  - If token_hash and type exist:
    - Create Supabase server client
    - Call `supabase.auth.verifyOtp({ type, token_hash })` (cast type as `EmailOtpType`)
    - On success: if `type === 'recovery'`, redirect to `/update-password`; otherwise redirect to `next` (only if starts with '/')
    - On error: redirect to `/auth/error?error={encodeURIComponent(error.message)}`
  - If missing token_hash: redirect to `/auth/error?error=Missing+token`

**Auth error page (`src/app/auth/error/page.tsx`):**
- Server Component (no interactivity needed)
- Same centered card layout
- Libre Baskerville heading: "Something went wrong"
- Read `error` from searchParams, display as body text
- Default message if no error param: "The link you followed may have expired or is invalid."
- Links: "Try logging in" → /login, "Request a new reset link" → /forgot-password
- Warm, non-alarming tone — this is a gift service, not a bank
- Note: In Next.js 15+, searchParams is a Promise — use `await props.searchParams` pattern
