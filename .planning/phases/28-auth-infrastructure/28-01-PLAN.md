  <action>
1. Run `npm install @supabase/supabase-js @supabase/ssr`

2. Create `src/lib/supabase/client.ts` — browser client factory:
   - Import `createBrowserClient` from `@supabase/ssr`
   - Export `createClient()` that calls `createBrowserClient(NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY)`
   - Use non-null assertions on env vars (they are required)

3. Create `src/lib/supabase/server.ts` — server client factory:
   - Import `createServerClient` and `CookieOptions` from `@supabase/ssr`
   - Import `cookies` from `next/headers`
   - Export `async function createClient()` that:
     - Awaits `cookies()` to get cookieStore
     - Creates server client with `getAll()` and `setAll()` cookie methods (NOT individual get/set/remove — those are deprecated and break sessions)
     - Wraps `setAll` in try/catch — Server Components cannot write cookies, middleware handles persistence
   - Use `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` env vars

4. Create `src/lib/supabase/middleware.ts` — updateSession utility:
   - Import `createServerClient` and `CookieOptions` from `@supabase/ssr`
   - Import `NextResponse` and `NextRequest` from `next/server`
   - Export `async function updateSession(request: NextRequest)` that:
     - Creates `supabaseResponse = NextResponse.next({ request })`
     - Creates server client with cookie methods that read from `request.cookies` and write to BOTH `request.cookies` AND `supabaseResponse.cookies`
     - Calls `await supabase.auth.getUser()` to trigger token refresh (NOT getSession — can be spoofed)
     - Returns `supabaseResponse` (NEVER create a new NextResponse after the client is created — this drops cookies)

5. Create `middleware.ts` at project root (next to package.json):
   - Import `updateSession` from `@/lib/supabase/middleware`
   - Export `middleware(request)` that delegates to `updateSession(request)`
   - Export `config.matcher` that excludes static assets: `'/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp)$).*)'`
   - This matcher ensures quiz funnel stays public (middleware runs but only refreshes tokens — no redirect logic here)

6. Add env vars to `.env.local`:
   - `NEXT_PUBLIC_SUPABASE_URL=` (user fills from Supabase Dashboard)
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY=` (user fills from Supabase Dashboard — check if project uses publishable key format instead)
   - Add comment: `# Supabase Auth — get from Dashboard > Settings > API`

Note: The env var is named `NEXT_PUBLIC_SUPABASE_ANON_KEY` because this Supabase project (aiypybffzqgmerkjehfn) was created before Nov 2025 and likely uses legacy anon key format. If Dashboard shows publishable key instead, rename to `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` and update client.ts and server.ts accordingly.
  </action>
