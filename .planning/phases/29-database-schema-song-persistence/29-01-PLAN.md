1. **Replace `src/db/schema.ts` entirely.** Remove all old table definitions (generations, outputs, generationStatusEnum, relations). Create:
   - `songStatusEnum` pgEnum with values: 'generating', 'completed', 'failed'
   - `songs` pgTable with these columns:
     - `id`: uuid, defaultRandom, primary key
     - `userId`: uuid('user_id'), nullable (null for anonymous)
     - `sessionToken`: text('session_token'), nullable (null after claim or for auth users)
     - `status`: songStatusEnum, notNull, default 'generating'
     - `heartbulaJobId`: text('heartbula_job_id'), notNull
     - `recipientName`: text('recipient_name'), notNull
     - `relationship`: text('relationship'), notNull
     - `genre`: text('genre'), notNull
     - `quizData`: jsonb('quiz_data'), notNull, $type with: occasion?, qualities?, memories?, message?, voiceGender?, language?
     - `r2WavKey`: text('r2_wav_key'), nullable
     - `r2Mp3Key`: text('r2_mp3_key'), nullable
     - `createdAt`: timestamp with timezone, defaultNow, notNull
     - `completedAt`: timestamp with timezone, nullable
     - `failedAt`: timestamp with timezone, nullable
   - Third argument array with:
     - RLS policies using `pgPolicy` from drizzle-orm/pg-core and `authenticatedRole`/`anonRole` from drizzle-orm/supabase:
       - `songs-authenticated-select`: for 'select', to authenticatedRole, using sql`user_id = auth.uid()`
       - `songs-authenticated-update`: for 'update', to authenticatedRole, using + withCheck sql`user_id = auth.uid()`
       - `songs-authenticated-delete`: for 'delete', to authenticatedRole, using sql`user_id = auth.uid()`
       - `songs-anon-deny-all`: for 'all', to anonRole, using sql`false`
     - Indexes: songs_user_id_idx on userId, songs_session_token_idx on sessionToken, songs_status_idx on status
   - Call `.enableRLS()` on the table (belt-and-suspenders per research)
   - Import `sql` from 'drizzle-orm' for RLS policy expressions

2. **Add to `src/lib/r2.ts`** two new helper functions (keep existing buildR2Key and buildR2Mp3Key for backward compat):
   - `buildSongR2WavKey(songId: string): string` returns `songs/${songId}/audio.wav`
   - `buildSongR2Mp3Key(songId: string): string` returns `songs/${songId}/audio.mp3`

3. **Create `src/db/schema.test.ts`** with tests verifying:
   - songs table is exported and has expected column names
   - songStatusEnum is exported with correct values
   - Old exports (generations, outputs, etc.) do NOT exist
   - buildSongR2WavKey and buildSongR2Mp3Key produce correct paths
  </action>
