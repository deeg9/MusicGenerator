**useGenerationStatus.ts** — `'use client'` directive.

Implement the polling hook exactly as specified in RESEARCH.md Pattern 2:
- Accepts `jobId: string | null`
- Returns `{ data: StatusResult | null, isPolling: boolean, elapsedSeconds: number, error: string | null }`
- Polls `GET /api/status/${jobId}` every 2500ms using `setInterval`
- Starts an elapsed-time counter updating every 1000ms
- Stops polling on terminal status (`completed` or `failed`)
- Cleanup: clears both intervals on unmount and when `jobId` changes (prevents stale closure / multiple simultaneous polls per RESEARCH.md Pitfall 2 and 3)
- On fetch error (network): keep polling (transient). On non-ok response: set error string and stop polling.
- Immediate first poll on mount (don't wait 2.5s)

**Submit handler:**
```typescript
async function handleSubmit(data: GenerationFormData) {
  setIsSubmitting(true);
  setJobId(null);           // Clear previous results (prevents stale poll per RESEARCH.md anti-pattern)
  setEnhancedCaption(null);

  try {
    const res = await fetch('/api/generate', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(data),
    });

    if (!res.ok) {
      const errorBody = await res.json().catch(() => null);
      const message = errorBody?.error?.message ?? 'Failed to start generation.';
      alert(message); // Simple for Phase 2; Phase 4 replaces with toast
      return;
    }

    const result = await res.json();
    setJobId(result.jobId);
    setEnhancedCaption(result.enhancedCaption ?? null);
  } catch {
    alert('Network error. Please check your connection and try again.');
  } finally {
    setIsSubmitting(false);
  }
}
```
