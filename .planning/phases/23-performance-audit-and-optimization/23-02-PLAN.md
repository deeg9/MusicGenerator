  <action>
Build and start the production server, then run Lighthouse CLI to measure Core Web Vitals.

Step 1: Build production bundle
```bash
npm run build
```

Step 2: Start production server on port 3000 in background
```bash
npm start &
# Wait for server to be ready
```

Step 3: Run Lighthouse against landing page
```bash
npx lighthouse http://localhost:3000 \
  --output=json \
  --output-path=./lighthouse-landing.json \
  --chrome-flags="--headless --no-sandbox" \
  --only-categories=performance \
  --quiet
```

Step 4: Extract and verify metrics
```bash
node -e "
const r = require('./lighthouse-landing.json');
const lcp = r.audits['largest-contentful-paint'].numericValue;
const cls = r.audits['cumulative-layout-shift'].numericValue;
console.log('LCP:', Math.round(lcp) + 'ms', lcp < 2500 ? 'PASS' : 'FAIL');
console.log('CLS:', cls.toFixed(4), cls < 0.1 ? 'PASS' : 'FAIL');
console.log('Performance Score:', Math.round(r.categories.performance.score * 100));
"
```

Step 5: Kill the production server

**If LCP > 2500ms:** Check the Lighthouse report for the LCP element. If it is an image, add priority loading. If it is text, check for render-blocking resources. Document findings.

**If CLS > 0.1:** Check the "Avoid large layout shifts" audit in the report. If font swap is the cause, consider `font-display: optional` or font preloading. Document findings.

**Important:** Do NOT measure against `next dev` — dev mode includes HMR overhead and gives inflated scores. Always use `next build && next start`.

Clean up: Remove lighthouse-landing.json after documenting results (or add to .gitignore).
