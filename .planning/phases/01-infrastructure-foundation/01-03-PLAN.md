  <action>
    **IMPORTANT:** Read `docs/ACESTEP-VALIDATION.md` first. If validation revealed different field names or behaviors than expected, adapt the implementation accordingly. The research says `prompt` is the style field and `[Instrumental]` is the lyrics tag -- but use whatever validation confirmed.

    1. Create `src/app/api/generate/route.ts` -- POST endpoint:
       - Parse JSON body: { prompt: string (required), lyrics?: string, genreTags?: string, duration?: number (default 120), instrumental?: boolean (default false) }
       - Validate input with basic checks: prompt must be non-empty string, duration must be 30-240
       - If instrumental is true, set lyrics to "[Instrumental]" regardless of provided lyrics
       - Call `submitGenerationJob` from `@/lib/runpod` with mapped parameters
       - Insert generation record via Drizzle: all input fields + runpodJobId from ACE-Step response + status 'pending' + startedAt now
       - Return JSON: { jobId: generation.id, status: 'pending' } with status 201
       - On error: use `classifyError` from `@/lib/errors`, update generation record with error info, return error response with appropriate HTTP status
       - CRITICAL: This endpoint returns immediately after submitting to ACE-Step. NO waiting for completion.

    2. Create `src/app/api/status/[jobId]/route.ts` -- GET endpoint:
       - Extract jobId from route params
       - Query generation from DB with outputs relation included
       - If not found: return 404 with error message
       - If generation.status is 'completed' or 'failed': return from DB cache (no RunPod call). Include outputs with presigned URLs if completed.
       - If generation.status is 'pending' or 'processing':
         a. Call `queryJobStatus(generation.runpodJobId)` from `@/lib/runpod`
         b. If ACE-Step status=1 (succeeded):
            - Download each audio file from ACE-Step using `fetchAudioBuffer`
            - Upload each to R2 using `uploadAudioToR2` with key from `buildR2Key(generation.id, variantIndex)`
            - Insert output records in DB (one per variant)
            - Update generation: status='completed', completedAt=now
         c. If ACE-Step status=2 (failed):
            - Classify error using `classifyError`
            - Update generation: status='failed', failedAt=now, errorType, errorMessage, retryable
         d. If ACE-Step status=0 (still running):
            - Update generation status to 'processing' if currently 'pending'
       - Return JSON: full generation object with status, timing, outputs (with presigned URLs if completed), error info (if failed)
       - CRITICAL: This endpoint makes ONE RunPod call and returns. No polling loop. The client polls THIS endpoint every 2.5 seconds.
       - Handle timeout on the RunPod call gracefully -- if the fetch to RunPod times out, return current DB state (still 'processing'), do NOT mark as failed.

    3. Create `src/app/api/audio/[key]/route.ts` -- GET endpoint:
       - The `key` param is a URL-encoded R2 object key (e.g., `generations%2Fabc123%2Foutput_0.wav`)
       - Decode the key, call `getAudioPresignedUrl` from `@/lib/r2`
       - Return JSON: { url: presignedUrl, expiresIn: 3600 }
       - On error: return 404 if key doesn't exist, 500 with classified error otherwise

    **Error response format (consistent across all routes):**
    ```json
    {
      "error": {
        "category": "model_error",
        "retryable": true,
        "message": "The AI model encountered an error. Please try again.",
        "technical": "ACE-Step returned status 2: CUDA out of memory"
      }
    }
    ```
    Per user decision: technical details included in response (dual-layer). No auto-retry.
