  <action>
    1. Create `docker/Dockerfile` extending the ValyrianTech image:
       ```dockerfile
       FROM valyriantech/ace-step-1.5:latest
       RUN apt-get update && apt-get install -y supervisor && rm -rf /var/lib/apt/lists/*
       COPY supervisord.conf /etc/supervisor/conf.d/acestep.conf
       RUN mkdir -p /workspace/logs
       CMD ["/usr/bin/supervisord", "-n", "-c", "/etc/supervisor/supervisord.conf"]
       ```
       Note: The stock image may already work without supervisord. User will test stock image first; if it crashes after 2-3 generations, they deploy this custom image instead.

    2. Create `docker/supervisord.conf`:
       ```ini
       [supervisord]
       nodaemon=true
       logfile=/workspace/logs/supervisord.log

       [program:acestep-api]
       command=uv run acestep-api
       directory=/app
       autorestart=true
       startretries=999
       stdout_logfile=/workspace/logs/acestep.log
       stderr_logfile=/workspace/logs/acestep.err.log
       stopasgroup=true
       killasgroup=true
       ```

    3. Create `scripts/validate-acestep.sh` -- a shell script that runs against a live RunPod pod:
       - Accepts RUNPOD_URL as first argument or from environment
       - Test 1: Health check -- GET to the base URL, confirm 200
       - Test 2: Basic generation -- POST /release_task with { prompt: "upbeat pop song, bright and cheerful", lyrics: "[Verse]\nTest lyrics line one\nTest lyrics line two\n\n[Chorus]\nTest chorus line", audio_duration: 30, batch_size: 1 }. Poll /query_result until status=1 or timeout at 90s. Record time taken.
       - Test 3: Instrumental mode -- POST /release_task with { prompt: "ambient electronic, soft pads", lyrics: "[Instrumental]", audio_duration: 30, batch_size: 1 }. Poll until complete.
       - Test 4: Dual variant -- POST /release_task with { prompt: "jazz piano, smooth", lyrics: "[Instrumental]", audio_duration: 30, batch_size: 2 }. Confirm 2 audio URLs in response.
       - Test 5: Sequential stress test -- Run 5 generations back-to-back (30s each, batch_size=1), checking /health between each. Record timing for each.
       - Output: Print results summary with pass/fail for each test, timing data, and any unexpected response fields
       - Use curl for HTTP calls, jq for JSON parsing

    4. Create `scripts/validate-acestep.ts` -- TypeScript version using the project's runpod.ts client (for running after Plan 01 code exists):
       - Imports from `@/lib/runpod`
       - Runs the same 5 test scenarios
       - Can be run with `npx tsx scripts/validate-acestep.ts`
       - Outputs structured results to console

    5. Create `docs/ACESTEP-VALIDATION.md` -- template for recording validation results:
       - Sections: Test Environment (GPU type, pod ID, image version), API Field Confirmation, Instrumental Mode, Custom Lyrics, Timing Data (table: test name, duration, status), Memory Leak Observations, Open Issues
       - Pre-fill with expected values from research; user/Claude fills in actual results after running validation
  </action>

<task type="checkpoint:human-action" gate="blocking">
  <name>Task 2: Deploy external services and validate ACE-Step</name>
  <what-built>
    Docker configuration for ACE-Step with supervisord crash recovery, and validation scripts to test the live API.
  </what-built>
  <how-to-verify>
    You need to set up three external services. Claude cannot do this because it requires account creation and billing setup.

    **Step 1: Create Supabase Project**
    1. Go to https://supabase.com/dashboard and create a new project
    2. Go to Project Settings -> Database -> Connection string
    3. Copy the "Transaction mode" pooler URL (port 6543, NOT 5432)
    4. Save as DATABASE_URL in `.env.local`

    **Step 2: Create Cloudflare R2 Bucket**
    1. Go to Cloudflare Dashboard -> R2
    2. Create a bucket named `music-generator-audio`
    3. Go to R2 -> Manage R2 API Tokens -> Create API Token (read+write permissions)
    4. Save the Account ID, Access Key ID, and Secret Access Key
    5. Go to bucket Settings -> CORS and add:
       ```json
       [{"AllowedOrigins": ["http://localhost:3000"], "AllowedMethods": ["GET"], "AllowedHeaders": ["content-type"], "MaxAgeSeconds": 3600}]
       ```
    6. Add all R2 env vars to `.env.local`

    **Step 3: Deploy RunPod Persistent Pod**
    1. Go to https://runpod.io -> Pods -> Deploy
    2. Select GPU: RTX 3090 or RTX 4090
    3. For the Docker image, first try stock: `valyriantech/ace-step-1.5`
    4. Expose HTTP port: 8000
    5. Mount volume at `/workspace`
    6. Start the pod and wait for it to be ready
    7. Copy the proxy URL: `https://{POD_ID}-8000.proxy.runpod.net`
    8. Save as RUNPOD_URL in `.env.local`

    **Step 4: Run Validation**
    ```bash
    bash scripts/validate-acestep.sh $RUNPOD_URL
    ```
    - If all 5 tests pass: great, stock image works
    - If pod becomes unresponsive after test 5 (sequential stress): build and deploy the custom Docker image from `docker/Dockerfile`, then re-run validation
    - Fill in `docs/ACESTEP-VALIDATION.md` with actual results

    **Step 5: Push Supabase Schema**
    After `.env.local` has DATABASE_URL:
    ```bash
    npx drizzle-kit push
    ```
    Verify tables exist in Supabase Dashboard -> Table Editor.
  </how-to-verify>
