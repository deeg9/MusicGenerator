    Update WaveformPlayer.tsx with two categories of changes:

    **A. CSS class token replacements:**
    - Play button: `bg-violet-600 text-white hover:bg-violet-500` -> `bg-primary text-primary-foreground hover:bg-primary/90`
    - Loading placeholder: `bg-zinc-800` -> `bg-muted`
    - Time display: `text-zinc-500` -> `text-muted-foreground`
    - Error text: `text-red-400` -> `text-destructive`

    **B. JS-level wavesurfer theme sync (CRITICAL -- follow RESEARCH.md Pattern 2 exactly):**
    1. Add imports: `import { useTheme } from 'next-themes';` and `import { getCssColorAsHex } from '@/lib/colors';`
    2. Add `const { resolvedTheme } = useTheme();` in component body
    3. Keep static placeholder values in useWavesurfer() init: `waveColor: '#888', progressColor: '#0ea5e9'`
       - Do NOT make these reactive -- that causes destroy/recreate cycle which interrupts audio
    4. Add a new useEffect AFTER existing event wiring effect:
       ```typescript
       useEffect(() => {
         if (!wavesurfer || !containerRef.current) return;
         const el = containerRef.current;
         wavesurfer.setOptions({
           waveColor: getCssColorAsHex('--muted', el),
           progressColor: getCssColorAsHex('--primary', el),
         });
       }, [wavesurfer, resolvedTheme]);
       ```
    5. This effect runs on mount (sets correct initial colors) and on every theme toggle (updates without audio interruption).

    **Anti-patterns to AVOID** (from RESEARCH.md):
    - Do NOT pass waveColor/progressColor as reactive props to useWavesurfer()
    - Do NOT use `theme` from useTheme() -- use `resolvedTheme`
    - Do NOT pass CSS var strings like 'var(--muted)' to wavesurfer -- use getCssColorAsHex
    - Guard setOptions() with `if (!wavesurfer || !containerRef.current) return;`
  </action>

  </verify>
